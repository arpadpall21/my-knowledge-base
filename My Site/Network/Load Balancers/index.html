Load Balancer Algorithms
Algorithm Description
Round Robin - Distributes incoming requests evenly across all available servers in a sequential order
Weight Round Robin - Enhanced Round Robin method which assigns a weight to each server based on its capacity, allowing more powerful servers to handle more requests
Least Connections - Directs traffic to the server with the fewest active connections
Least Response Time - Routes traffic to the server with the lowest average response time, ensuring faster processing of requests
- Monitors active connections and response times of servers and directs traffic to the one that is currently performing best (evolution of Least Connections)
IP Hash - Hashes the client's IP address, port and other attributes to determine which BE server will handle the request
- Same client will be always directed to the same server
- Load balancing usually results in a distribution of 49.8% to 50.2% (with large client base)
Adaptive (Dynamic) - Dynamically adjusts the distribution based on real-time performance metrics of BE servers
- We build logic based on backend servers performance (CPU, memory, response time, etc...) to determine how to distribute the traffic

- A load balancer is a system that distributes incoming network or application traffic across multiple servers so no single server becomes overloaded

- Load balancing exist on OSI layer:

OSI Layer 4 (transport layer): -> route traffic based on IP address and port

OSI Layer 7 (application layer): -> route based on HTTP/HTTPS details such as URL or host
