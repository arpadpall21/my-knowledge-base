Remember This :

- Platform Telemetry VS Application Telemetry

- Platform Telemetry -> Logs and metrics collected by Azure about the resource itself (like CPU usage, memory usage, access log, etc...)

- Application Telemetry -> Logs and metrics collected by the application itself (like request rates, response times, etc...)

Description and Demonstration :

- Azure Monitor

- It's a global (umbrella) service for monitoring and observability in Azure, it provides access to obervability features like Infrastructure health, Application performance, Logs and events, Alerts and notifications

- Diagnostic Settings -> Resource Level Observability Configuration (Platform Telemetry)

- Here can configure what kind of telemetry data is collected about the resource and where it should be sent (Log Analytics Workspace, Event Hub, Storage Account)

- Most of this telemetry data (logs, metrics, traces) are automatically collected and stored for 93 days (if we want to collect and store it, we need to configure it explicitly)

- (Application) Insights -> Application Level Observability Configuration (Application Telemetry)

- Instrument applications running in the resource and collects telemetry data about their performance, availability, and usage

- It's an easy to set up telemetry, but according to blogs it could be expensive

- Log Analytics Workspace -> Log data storage

- Data is stored in tables, the Log Analytics Workspace can be queried using Kusto Query Language (KQL)
