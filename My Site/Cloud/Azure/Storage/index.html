Description and Demonstration :

- Storage Account Account for 4 storage types (BLOB, File, Queue, Table)

- The underlying stored data is encrypted, either by default (Azure Storage Service Encryption (SSE)) or by using our keys (Customer Managed Key (CMK)) (Azure Key Vault)

- Lifecycle Management -> We can set rules to automatically do stuff like (move data to a cooler tier, delete data, etc... after a period of time)

- Object Replication -> Replicates data between storage accounts (the replicated data is readable on the destination storage account) (can be used for disaster recovery, data distribution, etc...)

- SAS (Shared Access Signature) -> grants restricted access rights to external users

Redundancy Options (Azure handles this for us "managed service")

- LRS (Local Redundant Storage) -> data is replicated within a single data center (3 copies) (durability: 99.999999999%)

- ZRS (Zone Redundant Storage) -> data is replicated across multiple availability zones within the same region (3 copies) (durability: 99.9999999999%)

- GRS (Geo Redundant Storage) -> data is replicated to a secondary region (minimum of 300 miles away) (3 copies in the primary region and 3 copies in the secondary region) (durability: 99.999999999999%)

- RA-GRS (Read Access Geo Redundant Storage) -> feature of GRS (gives read access to the secondary region)

Storage Types:

- Blob Storage -> File storage

- Files (BLOBs) are stored in Containers

- 3 tiers (speed VS price)

- Hot -> For frequently accessed data

- Cool and Cold-> For infrequently accessed data (more than 30 and 90 days respectively) (the data is accessible but essentially penalized for frequent access)

- Archive -> Low price (must be rehydrated before access)

- File Storage -> Stores files like the Blob Storage but supprots SMB (Server Message Block) protocol (files are accessible remotely, like we can create a remote drive from windows directly)

- Files are stored in Shares

- Queue Storage -> Queue accessible anywhere in the world via authenticated calls using HTTP(S)

- A single message size can be up to 64 KB

- Table Storage -> key-based NoSQL store

- Designed for fast data access and high volumes of data

- Data is stored in logical containers (tables), a table contains rows (entities) where the size limit is 1MB

- Rows are labeled by a PartitionKey and a RowKey (which is essentially a key for the stored data)

- CosmosDB works like table storage but offers much better global availability, speed and privacy features

- Accessible by various query languages (SQL, MongoDB, Table Storage, Cassandra, Germlin)

- Disk Storage various (HDD, SSD) attachable storage form VMs

- Managed disk -> The underlying storage is automatically managed, it also has better availability and security than unmanaged disk

- Unmanaged disk -> We have to managed the underlying storage, more flexible than unmanaged disk

- SQL Databases:

- MySQL

- PostgreSQL

- Microsoft SQL Server services:

- SQL Database

- SQL Managed Instance -> enhanced SQL Database with full access from the OS perspective (designed for organization migration on-premise SQL Server workloads)
